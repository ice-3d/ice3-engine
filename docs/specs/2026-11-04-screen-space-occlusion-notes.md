# 屏幕空间环境遮蔽：设计笔记与失败记录

> Document ID: ICE3-ENG-SPEC-007
>
> Status: Implemented
>
> Owner: ICE3 Engine maintainers

## 1. 为什么需要它

视口里物体和地面接触的地方没有暗部，所有面按同一个半球光照受光，于是建筑物、池体、
设备都像**浮**在地上。这是"塑料感"最直接的来源，比贴图分辨率影响大得多。

烘焙方案（把 AO 写进顶点色）对模型库是划算的，但 Studio 是建模工具：几何会被反复修改，
烘焙结果每次都失效。因此选择实时屏幕空间方案；烘焙留作未来对"完工资产"的可选增强。

## 2. 一次失败的尝试（2026-11-04）

### 2.1 做了什么

参照 `WebGL2ShadowMap` 的结构新增 `WebGL2SceneDepth`：深度 FBO（`DEPTH_COMPONENT24`）、
只写深度的极简着色器、随视口重建纹理；主着色器里加 8 方向 × 2 圈深度比较，邻居更靠近
相机就把间接光压暗。编译通过，webpack 构建成功。

### 2.2 结果

```
AO 前：meanLuminance 99.19 / brightPixels 991
AO 后：meanLuminance 99.19 / brightPixels 991   ← 一个像素都没变
```

### 2.3 排查与根因

1. 先怀疑只有深度附件的 FBO 在 WebGL2 里不完整，补了 `gl.drawBuffers([gl.NONE])` 与
   `gl.readBuffer(gl.NONE)`——**画面依旧完全一致**。
2. 真正的原因：深度 pass 只绘制了**实例化批次**（照抄阴影 pass 的循环），而控制台的瓦片
   集通过 `ICERenderBatch` 走的是**渲染批次**路径。深度图是空的 → 采样恒为 0 →
   所有比较相等 → 遮蔽恒为 0。

### 2.4 结论

`WebGL2RendererBackend.render()` 里有八处绘制循环（实例化批次、渲染批次、单体网格，
以及阴影/选择/拾取各自的变体）。**任何新增的屏幕空间通道都必须覆盖全部三条几何路径**，
试图"只复制一条路径、不碰原有代码"来省掉重构是行不通的——本笔记即为反例。

改动已全部回退；惰性代码（跑着但不生效）不应入库。

### 2.5 第三轮：深度通道通了，但遮蔽仍然看不见

补上着色器编译检查（`createShaderProgram` 抛错）后重做，并加了**深度可视化**开关
（把深度当灰度直接输出）。可视化结果：画面有内容、有轮廓，**说明深度通道本身是对的**
——之前"零像素变化"确实是通道没跑起来。

但把可视化关掉、接上深度差遮蔽后，画面只从 `99.19` 变到 `99.16`（0.03%），等于没有。

原因不是参数没调好，是**方法本身表达不了半径**：NDC 深度是非线性的，远端 10 米可能只差
千分之几，任何固定 bias 要么把所有遮挡当噪声滤掉、要么让整屏发黑。真正的 SSAO 需要
**把深度重建成视空间位置**，用世界半径选样本、用法线判断半球方向——这要求相机投影矩阵
及其逆矩阵（相机目前只暴露 `getViewProjectionMatrix`）。

结论：下一轮先给相机补 `getProjectionMatrix` / `getViewMatrix`，再按视空间重建 + 半径
采样重写遮蔽；深度可视化开关要保留在代码里，它是这条链路上唯一可信的验证手段。

## 3. 正确顺序

下面四步在 2026-11-04 已全部执行完毕，实测数据见第 5 节。

| 步骤 | 内容 | 验收 |
|---|---|---|
| 1 | 把三条几何路径的绘制抽成可复用遍历 `drawScene(program, pass)` | 同机位截图**逐像素一致** |
| 2 | 深度 pass 覆盖三条路径（渲染批次需按节点算 MVP） | 深度图非空：把深度可视化，应能看出轮廓 |
| 3 | 加 SSAO：**重建视空间位置**，按世界半径采样（不是 NDC 深度差） | 同机位 A/B 像素差 > 2%，接触处明显压暗 |
| 4 | 调参（半径、采样数、强度），在 SwiftShader 上确认可接受帧率 | 交互仍流畅 |

第 3 步的半径必须随视距变化：厂区跨度 600 米，写死世界半径会让近景糊、远景无感。

## 4. 边界

- 只覆盖实例化批次与渲染批次里**不透明**的几何；透明面不参与深度写入
- AO 只压暗间接光，不改变直射与自发光
- 屏幕空间方法的固有限制：画面外的遮挡物不可见、掠射角易出现条带，需要配合强度上限

## 5. 落地实现

### 5.1 深度通道

`WebGL2SceneDepth` 持有 `DEPTH_COMPONENT24` 的 FBO，随视口尺寸重建纹理；`drawBuffers`
设为 `NONE`，只写深度不写颜色。深度 pass 逐条覆盖**三条**几何路径——实例化批次、
渲染批次、落单的单体网格（`renderablesOutsideInstanceBatches`）——一条不落。
第 2 节那次失败就是漏了渲染批次；这次补渲染批次时又漏了第三条，症状更隐蔽：
瓦片之间有遮蔽，落单的设备却浮在地上，只在编辑单个物件时才看得出来。

阴影 pass 当时也只有一个路径（只画实例化批次），瓦片与落单网格都不投影；这条缺口
已在 SPEC-008 里补齐，两个通道现在覆盖同一批对象。

### 5.2 视空间重建与采样

片元着色器里不做 NDC 深度比较，而是把当前像素反算成视空间位置，再在这个空间里判断
"谁挡住了我"：

1. `viewPositionAt(uv)` 用 `tanHalfFov`、`aspect`、`near`、`far` 从深度纹理还原位置；
2. 法线取屏幕导数 `normalize(cross(dFdx(P), dFdy(P)))`——几何没有法线属性也不需要；
3. 世界半径换算成像素半径：`radius / (depth * tanHalfFov) * viewportY / 2`，
   所以同一个 2.5 米在近景是大圈、远景是小圈；
4. 逐样本求 `delta = P_sample - P_centre`，距离超过半径的丢弃，
   `dot(delta, N) / |delta| <= 0.15` 的丢弃（同一平面上不该互相遮蔽），其余按该夹角加权。

### 5.3 三圈采样

单圈 8 样本的半径是死的，接触处（10 厘米）和墙角（2 米）只能二选一。改成三圈后
每像素 24 样本，圈层按半径分摊权重：

| 圈 | 半径倍率 | 权重 | 负责的尺度 |
|---|---|---|---|
| 内 | 0.35 | 1.0 | 物体贴地的接触暗部 |
| 中 | 0.65 | 0.7 | 缝隙中部 |
| 外 | 1.0 | 0.45 | 大面积夹角、墙角 |

每像素旋转角用**交错梯度噪声**（IGN）而不是 `sin` 哈希：同样是逐像素扰动，但它在相邻
像素之间连续变化，采样缺口看起来像细密抖动而不是椒盐噪点。这一步不改变遮蔽总量，
只在扫视时看得出来。

### 5.4 调参通道

合适参数与场景尺度强相关，靠改常量重编译找太慢。`initialize` 时读一次页面地址：

- `?ao=<radius>,<strength>` 覆盖半径与强度，缺项按默认值；
- `?ao=off` 等价于强度 0。

它只影响渲染参数，不参与任何决策，默认值仍然是 2.5 米 / 0.30。

### 5.5 实测

固定机位（厂区全景、SwiftShader 软渲染、1440×900），同一次运行里依次切参数，
统计左侧画布区域：

| 参数 | 平均亮度 | 高光像素 | 3×3 高通残差 |
|---|---|---|---|
| 关闭 | 99.59 | 1088 | 5.564 |
| 2.5 / 0.35 | 95.03 | 833 | 5.620 |
| 2.5 / **0.30**（默认） | 95.70 | 878 | 5.577 |
| 2.5 / 0.28 | 95.97 | 907 | 5.562 |

第三圈确实多找到了遮蔽：同一批资产上，双圈 0.35 时整帧 96.36、三圈同参数 94.65，
差 1.7 个亮度点，不是单纯把画面抹平。所以默认强度从 0.35 回调到 0.30——
相对无遮蔽基线少掉 3.9% 亮度、高光少 19%，接触暗部仍然清楚。

`?ao` 通道让这套对比变成"改地址栏"而不是"改常量重编译"，上面四行是同一次进程内
连续测出来的，排除了构建差异。

### 5.6 为什么没有模糊通道

`grain` 一列是无遮蔽基线 5.564 与三圈 5.577 的对比——差 0.2%，且这个指标本身还被
贴图细节占满。也就是说噪点在静帧里已经看不见，加一个双通道模糊（额外的 FBO + 全屏
两趟 + 深度感知权重）换不来可感知的质量提升，反而要多一次全屏带宽。留作以后
真正出现可见噪声（例如样本数降到 8）时的选项。

## 6. 仍未做

- 帧耗时：三圈 24 样本没有在真实 GPU 上量过，SwiftShader 下的差值也不代表移动端；
- 法线贴图与遮蔽的耦合：目前用屏幕导数法线，法线贴图扰动不参与遮蔽方向判断；
- 掠射角条带：外圈在极浅视角下仍会有轻微条纹，需要配合视角相关衰减。
