# ICE3 M0 Public API

> Document ID: ICE3-ENG-API-001
>
> Status: Active
>
> Owner: ICE3 Engine maintainers
The `ice3` package is the only supported consumer entry. M0 exposes a focused API for scene rendering and 2D/3D composition.

## Complete example

```ts
import {
  ICE3,
  ICEBasicMaterial,
  ICEBoxGeometry,
  ICELabel,
  ICEMesh,
  ICEOrbitController,
  ICEPerspectiveCamera,
  ICEScene,
  ICEScreenLayer,
  ICEWorldLayer,
} from 'ice3';

const host = document.querySelector<HTMLElement>('#stage');
if (!host) throw new Error('Missing stage');

const engine = new ICE3().init(host);
const scene = new ICEScene({ id: 'scene' });
const camera = new ICEPerspectiveCamera({
  id: 'camera',
  fov: 45,
  near: 0.1,
  far: 100,
  position: [3, 2, 5],
  target: [0, 0, 0],
});

const block = new ICEMesh({
  id: 'block',
  geometry: new ICEBoxGeometry({ width: 1, height: 1, depth: 1 }),
  material: new ICEBasicMaterial({
    color: '#2f81f7',
    edgeColor: '#e6f2ff',
  }),
});
scene.addChild(block);

const worldLayer = new ICEWorldLayer({ id: 'world', order: 0 });
worldLayer.addChild(
  new ICELabel({ id: 'block-label', text: 'Block', anchorId: 'block' }),
);

const hudLayer = new ICEScreenLayer({ id: 'hud', order: 10 });
hudLayer.addChild(
  new ICELabel({
    id: 'status',
    text: 'Running',
    screenPosition: [24, 24],
    interactive: true,
  }),
);

const orbit = new ICEOrbitController(engine, camera).start();
engine
  .setScene(scene)
  .setCamera(camera)
  .addLayer(worldLayer)
  .addLayer(hudLayer)
  .start();

// Release every frame request, DOM listener, layer, and GPU resource.
orbit.dispose();
engine.destroy();
```

## Engine

### `new ICE3(options?)`

Creates an engine instance.

Options:

- `backend`: inject a renderer backend. Production defaults to the WebGL2 backend.
- `scheduler`: inject a frame scheduler. Production defaults to the browser frame scheduler.

### `init(target)`

Binds an `HTMLElement`, Canvas element, or selector. The method creates or configures the scene canvas and transparent 2D overlay, initializes the backend, and applies the current viewport.

Can be called once. Repeated initialization fails with `ICE3_ALREADY_INITIALIZED`.

### `setScene(scene)` and `setCamera(camera)`

Set the active scene and perspective camera. The engine does not render until both are present.

### `addLayer(layer)` and `removeLayer(layer)`

Add or remove a layer. Lower `order` values paint first. Equal orders keep insertion order; later equal-order layers are hit first.

### `start()`, `stop()`, and `requestRender(reason?)`

`start()` is idempotent and enables on-demand rendering. `requestRender()` coalesces requests into one pending frame. `stop()` cancels pending work without destroying resources.

### `project(position)`

Converts a world position into CSS pixels relative to the 3D viewport.

Returns `{ x, y, visible, depth }`.

### `getSelection()` and `setSelection(ids)`

Read or replace the shared semantic selection set. Selection changes emit `SELECTION_CHANGE`.

Selection is committed on short click release, not pointer down. Movement up to
four CSS pixels remains a click; longer pointer journeys remain camera drags
even if the pointer returns to its start. Interactive 2D controls do not
trigger or clear 3D selection.

### `pick(point)`

Returns the nearest visible scene node under a viewport point. The result uses the same stable node identity as selection and 2D labels.

When the active backend supports exact picking, `pick()` renders an offscreen
identity image and reads the visible surface at the requested pixel. Test
backends without that capability use the semantic fallback.

### `getDiagnostics()`

Returns frame ID, FPS, CPU frame time, backend capabilities, scene and layer counts, DPR, viewport, context-loss count, label rectangles, and the last diagnostic. It exposes no Canvas, WebGL, or painter objects.

### `resize()` and `destroy()`

`resize()` recalculates the host viewport and DPR. `destroy()` is idempotent and releases scheduled frames, input listeners, layers, generated canvases, and renderer resources.

## Scene model

### `ICENode`

Accepts `{ id, position?, rotation?, scale? }`. Nodes own stable IDs, parent/child links, visibility, transforms, event listeners, and JSON serialization.

Duplicate IDs, scene cycles, and invalid IDs are rejected.

### `ICEScene`

Scene root with type ID `ice3:Scene`.

### `ICEMesh`

Combines a stable node ID with `ICEBoxGeometry` and `ICEBasicMaterial`.

### `ICEBoxGeometry`

Accepts positive `width`, `height`, and `depth` values. Type ID is `ice3:BoxGeometry`.

### `ICEBasicMaterial`

Accepts a CSS hexadecimal base color and an optional `edgeColor`. Rendering is
unlit by default, so geometry remains uniformly colored; `edgeColor` adds a
high-contrast geometry outline. Type ID is `ice3:BasicMaterial`.

### `ICEPerspectiveCamera`

Accepts `id`, `fov`, `near`, `far`, `position`, and optional `target`. Use `setPosition()` and `setTarget()` for camera updates.

## 2D layers

### `ICEWorldLayer`

Paints labels anchored to scene IDs. Missing anchors make the label invisible and produce `ICE3_UNKNOWN_ANCHOR`.

### `ICEScreenLayer`

Paints labels at explicit screen positions.

### `ICELabel`

Accepts `id`, `text`, and either `anchorId` or `screenPosition`. Optional fields are `color`, `background`, `padding`, and `interactive`.

## Interaction

### `ICEOrbitController`

`start()` subscribes to shared engine events; `stop()` releases them; `dispose()` permanently closes the controller.

Dragging from geometry or empty 3D space starts a damped orbit. Wheel and pinch
zoom are also damped. An interactive 2D label consumes the gesture and does not
start camera orbit. WASD and the matching arrow keys pan the camera and its
target across the view plane without changing the zoom distance; releasing a
key stops movement. Editable controls retain normal keyboard input.

## Serialization and registration

- `serializeScene(scene)` creates a schema version 1 scene snapshot.
- `deserializeScene(snapshot, registry)` returns a restored scene plus structured errors.
- `ICETypeRegistry.register(typeId, type)` enforces unique type IDs and unique constructors.

## Errors and types

- `ICEEngineError` carries a stable `code`, message, optional details, and optional diagnostic.
- `ICEDiagnostic` contains severity, code, message, path, and details.
- `ICEEngineDiagnostics` is the read-only diagnostic snapshot returned by `getDiagnostics()`.
