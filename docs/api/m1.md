# ICE3 M1 Asset API

`ice3` remains the only supported public entry. M1 adds loading for
`ICE3 Prepared GLB Profile v1` files generated by `ice3-toolchain`.

## Complete example

```ts
import {
  ICE3,
  ICEOrbitController,
  ICEPerspectiveCamera,
  ICETilesetLoader,
} from 'ice3';

const host = document.querySelector<HTMLElement>('#stage');
if (!host) throw new Error('Missing stage');

const engine = new ICE3().init(host);
engine.setBackgroundColor('#000000');
const camera = new ICEPerspectiveCamera({
  id: 'camera',
  fov: 45,
  near: 0.1,
  far: 1000,
  position: [3, 2, 5],
  target: [0, 0, 0],
});
const orbit = new ICEOrbitController(engine, camera).start();
const tileset = await new ICETilesetLoader(engine, { camera }).open(
  '/assets/partitioned/tileset.json',
);

engine
  .setScene(tileset.scene)
  .setCamera(camera)
  .start();

await tileset.whenReady();
// Continue working while remaining partitions load.
await tileset.whenIdle();

// Idempotently detach and dispose every loaded partition.
tileset.dispose();
orbit.dispose();
engine.destroy();
```

### Camera controls

The example camera supports drag rotation, wheel zoom, and keyboard movement.
Hold WASD or the matching arrow keys to pan across the view plane without
changing the zoom distance. Movement continues while a key remains pressed and
stops when it is released. The example keeps a compact control hint in the
lower-left corner after loading; it does not intercept pointer input.

For prepared assets, one named mesh node is one selectable equipment unit.
Multiple primitives from the same source node share one selection identity.
Short-clicking visible geometry selects the equipment and applies a yellow
highlight without modifying source materials. The example shows selected
equipment details in a fixed upper-right panel rather than a label over the
model. Missing business fields use deterministic demonstration data. Clicking
empty space clears the selection.

### Loading feedback

The example renders a full-stage loading overlay before the scene is ready.
The overlay exposes `role="status"`, updates the stage `aria-busy` state, locks
asset disposal while loading, fades out after the first rendered scene, and
keeps an explicit error state visible when loading fails.

### `engine.setBackgroundColor(color)`

Sets the WebGL scene clear color from a hexadecimal color. The default remains
the dark engineering canvas used by M0. The M1 asset example uses black so the
asset's own display colors remain the primary source of visual separation.

## `ICEAssetLoader`

```ts
new ICEAssetLoader(engine, options?)
```

Options:

- `fetch`: custom request implementation. Production defaults to
  `globalThis.fetch`.
- `verifyIntegrity`: when `true`, performs one SHA-256 scan of the BIN chunk.
  Default is `false` to avoid duplicating large-buffer reads during normal
  loading.

### `load(url, options?)`

Returns `Promise<ICEAssetHandle>`.

- `options.signal`: optional `AbortSignal`.
- Concurrent loads of the same URL share immutable decoded bytes.
- Every successful call creates an independent scene instance.
- Failed or aborted requests do not enter the reusable cache.

### `clear()`

Clears cached immutable asset bytes. Existing scene handles are unaffected.

## `ICEAssetHandle`

```ts
{
  id: string;
  scene: ICEScene;
  bounds: {
    min: [number, number, number];
    max: [number, number, number];
  };
  stats: {
    nodeCount: number;
    maxNodeDepth: number;
    meshCount: number;
    primitiveCount: number;
    triangleCount: number;
    edgeSegmentCount: number;
    materialCount: number;
    selectionGroupCount: number;
  };
  contract: {
    status: 'active' | 'legacy';
    version?: string;
    preparation?: Record<string, unknown>;
    budget?: {
      profile: string;
      status: 'pass' | 'warning' | 'error';
      warningCount: number;
      errorCount: number;
    };
  };
  dispose(): void;
}
```

`dispose()` is idempotent. It disposes the loaded scene tree and requests a
frame so the renderer releases geometry buffers that are no longer referenced.

`contract.status` is `legacy` for older prepared assets without the shared
contract. The engine reports a warning for those assets and fills missing
statistics from the actual GLB structure.

## `ICETilesetLoader`

```ts
new ICETilesetLoader(engine, {
  fetch,
  camera,
  maxConcurrentTiles: 2,
  maxResidentTiles: 24,
  maxResidentBytes: 268435456,
  prefetchMarginRatio: 0.10,
  unloadMarginRatio: 0.20,
  maxCommitsPerFrame: 1,
});
```

Options:

- `fetch`: custom request implementation.
- `camera`: required camera used to calculate the visible work set.
- `maxConcurrentTiles`: positive request concurrency. Default is `2`.
- `maxResidentTiles`: soft resident partition limit. Default is `24`.
- `maxResidentBytes`: soft resident geometry-byte limit. Default is `256 MiB`.
- `prefetchMarginRatio`: preload frustum expansion relative to scene radius.
  Default is `0.10`.
- `unloadMarginRatio`: unload frustum expansion relative to scene radius.
  Default is `0.20` and must exceed the prefetch ratio.
- `maxCommitsPerFrame`: maximum completed partitions committed to the scene per
  frame. Default is `1`.

### `open(url, options?)`

Fetches and validates `tileset.json`, creates an empty unified scene, starts
partition loading, and returns `Promise<ICETilesetHandle>` without waiting for
all tile content. Relative Tileset URLs are resolved against the current page.
`options.signal` aborts the index request and pending partition requests.

### `ICETilesetHandle`

```ts
{
  scene: ICEScene;
  bounds: ICEGeometryBounds;
  stats: {
    total: number;
    pending: number;
    loading: number;
    loaded: number;
    failed: number;
    evicted: number;
    visible: number;
    resident: number;
    residentBytes: number;
  };
  tileState(tileId: string): 'pending' | 'loading' | 'loaded' | 'failed' | 'evicted' | undefined;
  whenReady(): Promise<void>;
  whenIdle(): Promise<void>;
  dispose(): void;
}
```

`whenReady()` resolves after the first partition is committed. If the first
failed partition settles before any success, it rejects while remaining
concurrent partitions continue. `whenIdle()` settles when the current work set
has no pending, loading, or waiting-to-commit partitions. It watches the work
set captured at call time; a later camera change is a new work-set cycle and
does not extend an earlier `whenIdle()` call.

`whenComplete()` is intentionally absent. A camera-driven Tileset does not
promise to keep every partition resident, so a global-completion promise would
encode the wrong lifecycle.

Each tile has one of these states:

- `pending`: desired by the current work set but not yet requested.
- `loading`: requested or being prepared for scene commit.
- `loaded`: committed to the unified scene and resident.
- `failed`: the current attempt failed.
- `evicted`: outside the retention set, discarded before commit, or released.

The handle emits:

- `TILESET_TILE_LOADING`
- `TILESET_TILE_LOADED`
- `TILESET_TILE_FAILED`
- `TILESET_TILE_UNLOADED`
- `TILESET_READY`
- `TILESET_IDLE`

Each event parameter contains an immutable `stats` snapshot and a `tileId` for
tile-specific events. A failed partition keeps previously loaded partitions in
the scene and reports `ICE3_TILESET_TILE_FAILED`. Partitions outside the unload
frustum are removed atomically from the unified scene and their decoded cache
entry is released. If the active selection belongs to the removed partition,
the engine clears that selection before disposal. `TILESET_IDLE` reports when
the current work set has settled.

### Supported Tileset subset

- 3D Tiles 1.1 `asset.version`.
- Explicit `children` trees.
- Local Cartesian `box` or `sphere` bounding volumes.
- Relative `content.uri` references to ICE3 Prepared GLB files.
- Finite 4x4 `transform`.
- `REPLACE` refinement.

`region`, external Tilesets, `implicitTiling`, unsupported content, and
undeclared required extensions fail with `ICE3_TILESET_UNSUPPORTED`.

Visible partitions always take priority over the resident budget. A warning is
reported when the visible set exceeds that soft budget, but no visible equipment
is removed. Offscreen prefetch is suppressed while the budget is exceeded.
`residentBytes` is the sum of prepared position, index, edge, and color buffers
for resident partitions; it is an explicit geometry-byte estimate rather than a
GPU-driver memory report.

The loader listens to rendered camera and viewport changes. It recomputes the
work set only when the view-projection matrix or viewport changes, reorders
requests by visible status and distance, and discards stale candidates before
they reach the scene. Partitions are always wrapped in a removable container,
including identity-transform tiles, so unload never removes sibling geometry.

The runtime does not synthesize LOD in this release. `dispose()` releases every
resident partition and the complete unified scene exactly once.

Generated LOD, parent-content refinement, implicit tiling, external Tilesets,
and screen-space-error selection remain future stages.

## Profile boundary

The loader accepts only a GLB carrying:

```json
{
  "asset": {
    "extras": {
      "ice3": {
        "profile": "ice3-prepared",
        "profileVersion": "1.0"
      }
    }
  }
}
```

The profile requires matrix node transforms, triangle and line primitives,
non-normalized float positions, unsigned scalar indices, one BIN chunk, and no
external resources. Animation, skins, Morph targets, textures, images, cameras,
lights, sparse accessors, and required extensions are rejected.

An ordinary GLB must first be processed by `ice3-toolchain`. Importing the
toolchain or a source-format adapter into the browser runtime is unsupported.

## Generic geometry

`ICEIndexedGeometry` exposes prepared position, triangle-index, and optional
edge-index arrays. `ICEMesh` accepts either `ICEBoxGeometry` or
`ICEIndexedGeometry`.

```ts
import { ICEIndexedGeometry } from 'ice3';

const geometry = new ICEIndexedGeometry({
  id: 'triangle',
  positions: new Float32Array([0, 0, 0, 1, 0, 0, 0, 1, 0]),
  indices: new Uint16Array([0, 1, 2]),
});
```
