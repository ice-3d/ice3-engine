# ICE3 Engine M0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build a runnable ICE3 M0 vertical slice with one 3D scene, one world-anchored 2D label, one screen-anchored HUD, shared input routing, explicit lifecycle management, and browser-level verification.

**Architecture:** Use an npm workspace with four packages: pure core models, a renderer contract plus WebGL2 backend, a runtime/compositor, and one public entry package. Develop in dependency order, keeping all browser and GPU access outside the core package, then integrate the pieces through a single example.

**Tech Stack:** Node.js `>=24`, npm `>=11`, TypeScript `7.0.2`, node-test `5.0.5`, Playwright `1.64.1`, test-tooling `8.3.5`, native WebGL2.

**Spec:** `docs/superpowers/specs/2026-10-27-engine-m0-design.md`

## Global Constraints

- Public consumers import only from `ice3`; internal package paths are private.
- `@ice3/core` has no runtime dependencies and cannot reference DOM, Canvas, GPU, sibling packages, or the public umbrella package.
- Dependency direction is `@ice3/core` ← `@ice3/renderer` ← `@ice3/runtime` ← `ice3`.
- M0 uses ESM and generated TypeScript declarations; CJS and UMD are outside M0.
- The browser backend uses WebGL2 only, with no WebGL1 fallback.
- The renderer creates no public GPU objects; external APIs use semantic IDs and ICE-owned types.
- Public events use `on`, `off`, and `once`; `off` matches the original function reference.
- Every serializable object uses canonical type IDs in the form `ice3:TypeName`.
- The M0 example runs at port `8103` and Playwright never reuses an existing server.
- Every document, comment, example, identifier, package name, and directory name follows the ICE3 naming and legal constraints.
- No third-party runtime dependency is added in M0.
- The renderer, runtime, and example are tested in current Chromium, Firefox, and WebKit.
- M0 does not add loading, LOD, instancing, industrial semantics, Agent integration, asset tools, or post-processing.

## Review Focus

- WebGL2 unavailable or the GPU context is lost after initialization: initialization must fail predictably or the engine must emit recovery events without duplicate listeners.
- Two nodes or layers claim the same identity: the second registration must be rejected and must not corrupt selection or anchors.
- A pointer begins on a 2D control and crosses into the 3D viewport: the original target keeps capture until release.
- The container is resized or DPR changes while a world label is visible: the label remains within one CSS pixel of its projected node.
- The engine is started, stopped, destroyed, and rebuilt repeatedly: no frame requests, listeners, GPU handles, or overlay canvases remain after destruction.
